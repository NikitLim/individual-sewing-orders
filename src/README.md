# Учебная практика — КТ2: индивидуальный пошив

**Студент:** Лимонов Н. А. · **Группа:** ИКБО-10-24  
**Бизнес-процесс:** оформление и подготовка индивидуального заказа на пошив к передаче в производство.  
**Язык:** Python **3.12** (процедурный стиль); внешние зависимости отсутствуют.

## Запуск

```bash
cd src
python main.py
```

Для своего JSON-файла и номера заказа:

```bash
python main.py --data demo_data.json --order 1001
```

Тесты (из папки `src`):

```bash
python -m unittest -v test_main.py
```

## Возможности

- `check_order_completeness()` — сверка обязательных полей и мерок;
- `check_material_availability()` — проверка обеспеченности материалами, вложенный поиск, O(n·m);
- `calculate_order_cost()` — сумма материалов и работ, O(p+q);
- `form_production_task()` — выдача задания только для согласованного и полного заказа.

Данные представляются обычными `dict` и `list`, хранятся в `demo_data.json`, названия коллекций и полей согласованы с логической ER-моделью. Собственные классы, `@dataclass`, `NamedTuple`, `Enum` и глобальные изменяемые переменные не используются. Все цены — целое количество копеек (без ошибок округления).

Все сведения о заказчике в `demo_data.json` являются обезличенными учебными данными. Реальные контактные данные в публичный репозиторий не загружаются.

## Ограничения

На КТ2 — учебный консольный прототип, не промышленная система. Данные не записываются обратно в JSON, складские остатки не резервируются. На КТ3 предусмотрена ООП-версия на Java, на КТ4 — проектирование и подключение реляционной БД.
